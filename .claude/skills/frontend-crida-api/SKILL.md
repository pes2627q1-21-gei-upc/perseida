# Frontend: crida a l'API

Genera i usa el client tipat de l'API (openapi-typescript + openapi-fetch) i exposa-lo com a hooks de TanStack Query dins cada feature. El contracte és l'OpenAPI del backend: no s'inventen camps.

Segueix el protocol `vault-context` (AGENTS.md) i les ADR vigents. La conversió d'errors, els toasts i les traduccions per `code` es defineixen a la skill `gestio-errors`: aquí només es lliga el middleware i s'hi remet.

## Quan usar-la / quan NO
- Usa-la: nou hook `useX`/`useXMutation` a `src/features/<mòdul>/{hooks,api}`, configuració del client a `src/shared/api`, regeneració de tipus.
- NO: UI (`frontend-component`, `frontend-pagina`), validació de formularis (`frontend-formulari`), disseny dels errors/toasts (`gestio-errors`), lògica de negoci (viu al backend), offline/SQLite outbox (pregunta a l'humà si hi afecta; vegeu ADR 0011).

## Protocol de dubtes (OBLIGATORI)
No inventis res. Si falta qualsevol dada o hi ha més d'una opció raonable, ATURA'T abans d'escriure codi i pregunta a l'humà (si ets un subagent que no pot preguntar: retorna a l'agent principal un bloc `PREGUNTES PER A L'HUMÀ` amb les preguntes numerades i les opcions). Mai assumeixis un valor per defecte en silenci.

Preguntes concretes d'aquesta skill (abans d'escriure):
1. On és l'esquema OpenAPI (URL/fitxer del backend) i com es regenera? Està l'endpoint ja a l'OpenAPI? Si no hi és, no l'inventis: cal que el backend el publiqui.
2. Quina és la base URL per entorn (via variable d'entorn pública d'Expo; mai secrets)? Com s'adjunta el token de sessió (auth Google OAuth2+PKCE; ADR 0008)?
3. Política de cache per a aquesta dada: `staleTime`, reintents, invalidació després de mutacions, paginació/infinite query?
4. La dada ha de funcionar offline (cache de lectura/outbox SQLite) o és només en línia?
5. Cal optimistic update? (només si l'humà ho aprova; el servidor és la font de veritat)
6. Dependències noves (`openapi-typescript`, `openapi-fetch`, `@tanstack/react-query`) ja instal·lades? Si no, pregunta abans d'afegir-les; versió fixada amb pnpm (verifica'n l'existència).

## Passos
1. Llegeix el vault (frontend.md, contracte d'API) i l'OpenAPI actual; troba l'operació exacta (`operationId`, camins, esquemes).
2. Genera/actualitza els tipus amb `openapi-typescript` cap a un fitxer generat (no s'edita a mà; sense commits de canvis manuals). L'script de generació va a `package.json` (pregunta el nom/ubicació).
3. `src/shared/api/client.ts`: una única instància d'`openapi-fetch` (`createClient<paths>`) amb base URL de config i un **middleware** que: adjunta credencials, i quan la resposta no és `ok` llegeix `application/problem+json` (`type,title,status,detail,instance,code,errors?`) i llença un `AppError` (definit segons `gestio-errors`). Errors de xarxa/offline també es converteixen en `AppError`.
4. Per feature, a `api/` una funció fina sobre el client i a `hooks/` el hook de TanStack Query: `useQuery` (lectura) o `useMutation` (escriptura), amb **query keys** centralitzades per feature i invalidació explícita en mutar.
5. El hook retorna `data`, `isLoading`, `isError`, `error` (`AppError`); la UI decideix loading/empty/error (`frontend-pagina`). No es mostra mai el cos cru ni la traça.
6. Missatge a l'usuari: el mostra l'ErrorBoundary/toast traduint `code` (`gestio-errors`); el hook no construeix text.
7. Escriu els tests (després del codi) i passa la checklist.

## Plantilla de codi (orientativa: el repo encara no té codi)
```ts
// src/shared/api/client.ts (illustrative)
import createClient, { type Middleware } from 'openapi-fetch';
import type { paths } from './schema'; // generated by openapi-typescript

const errorMiddleware: Middleware = {
  async onResponse({ response }) {
    if (response.ok) return undefined;
    // Convert problem+json into AppError; details in the gestio-errors skill.
    throw await toAppError(response);
  },
};

export const api = createClient<paths>({ baseUrl: config.apiBaseUrl });
api.use(errorMiddleware);
```
```ts
// src/features/events/hooks/useEvent.ts (illustrative)
import { useQuery } from '@tanstack/react-query';
import { api } from '@/shared/api/client';

export const eventKeys = { detail: (id: string) => ['events', id] as const };

export function useEvent(id: string) {
  return useQuery({
    queryKey: eventKeys.detail(id),
    queryFn: async () => {
      const { data } = await api.GET('/events/{event_id}', { params: { path: { event_id: id } } });
      return data!; // the middleware already throws AppError on failures
    },
  });
}
```
Els camins i noms són d'exemple: s'han de prendre de l'OpenAPI real. Versions fixades amb pnpm; pregunta/verifica.

## Tests (després del codi)
- Jest + RNTL: renderitza el hook amb un `QueryClientProvider` de prova i el client simulat (`frontend/__mocks__/`); comprova estats loading/èxit/error i que un problem+json esdevé `AppError` amb el `code` correcte.
- Mutacions: invalidació de les query keys correctes; no es dispara si el servidor falla.
- Cobertura de hooks >=70% (convencions/testing.md). No hi ha tests e2e.

## Checklist final
- [ ] Protocol `vault-context` seguit; l'operació existeix a l'OpenAPI; cap camp inventat.
- [ ] Tipus generats, no escrits a mà ni editats.
- [ ] Cap `fetch` solt ni URL hardcodejada; tot via el client `openapi-fetch`.
- [ ] Middleware problem+json -> `AppError` (segons `gestio-errors`); xarxa/offline cobert.
- [ ] Hook per feature amb query keys centralitzades i invalidació explícita.
- [ ] Cap missatge d'error construït al hook; cap JSON/traça a la UI.
- [ ] Cap secret ni token al codi; base URL per config.
- [ ] Tests de hooks escrits; cap dependència nova sense permís.

## Què NO fer
- No usis `fetch`/axios solts ni concatenis URLs.
- No inventis camps, endpoints ni codis d'error: el contracte és l'OpenAPI.
- No posis regles de negoci o de seguretat al client (frontend "tonto").
- No dupliquis la gestió d'errors: remet a `gestio-errors`.
- No guardis secrets ni dades personals; no editis `.claude/skills/`.
